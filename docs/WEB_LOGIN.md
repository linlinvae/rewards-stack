# 网页登录验证

[返回首页](../README.md) · [文档目录](README.md)

此扩展在 Dashboard 所有页面显示待处理的登录验证请求，支持补全验证邮箱、输入六位邮箱验证码，以及微软已呈现的 TOTP 动态码输入页。不提供 CAPTCHA、通行密钥或完整远程浏览器操作。

升级后强制刷新页面，在“账号”中对新账号选择“仅运行此账号”。保持面板打开；脚本进入人工输入步骤时会弹窗。按提示输入验证邮箱，再输入微软发送的验证码。微软接受验证并完成登录后，由原脚本保存该账号会话，无需覆盖或迁移整个会话数据库。

每个请求等待最多 180 秒。可以“稍后填写”后通过顶部横幅重新打开；取消、过期或连接失败会终止当前登录验证，重新运行该账号才能重试。验证码错误时，是否出现下一次输入取决于微软页面和上游脚本的重试逻辑。

请求只保留在 Script API 的内存中，按任务及邮箱隔离。验证码不写配置、SQLite、日志或浏览器存储。页面刷新可重新读取仍有效的请求；停止任务、服务重启或过期会清除请求。脚本子进程通过容器内回环地址及每次任务更新的密钥取得一次性输入；网页仍使用现有面板认证和同源 JSON 写入校验。登录相关内容应仅在受信任网络或 HTTPS 面板中输入。

构建在固定版本的 API、登录工具和状态机源码上安装受 SHA-256 保护的扩展。网页输入可用时，优先处理已呈现的邮箱验证页；登录方式选择页有邮箱验证码选项时优先使用它。已有正常会话仍走原来的会话恢复逻辑。

本地验证：`TEST_VARIANT=zh-CN node tests/integration.mjs`、`node --test tests/login-broker.test.mjs` 和现有账号、启动保护、中文显示测试。测试使用隔离服务、模拟账号和真实的已修改输入工具，不联系微软、不执行积分任务。真实登录结果及容器部署须在 NAS 升级后人工验收。

本仓库已包含此扩展。部署及更新前确认任务空闲、计划关闭并备份，重建后验证原账号及会话记录保留。源码归档方式见 [docs/PUBLISHING.md](PUBLISHING.md)；历史机器专用安装器及 SSH 运维脚本不随仓库发布。
